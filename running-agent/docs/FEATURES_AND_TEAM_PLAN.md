# Running Agent 项目概况与后续方向

## 项目基本信息

Running Agent（STRIDE OS）是一个本地优先的跑步训练分析与 AI 教练应用。用户可以配置自己的大模型 API，导入跑步数据，查看训练趋势，并通过 AI 教练分析近期表现、训练负荷和后续训练安排。

当前应用包含训练总览、训练记录和 AI 教练三个独立页面。数据来源支持 CSV、GPX、TCX 文件上传，以及通过 MCP 同步第三方运动平台记录。训练活动、导入记录和对话保存在本地 SQLite 中，模型密钥不写入数据库。当前版本面向单用户本地运行，尚未加入账号体系、多租户和云端同步。

## 当前技术栈

| 层级 | 技术 | 当前用途 |
|---|---|---|
| 前端 | HTML、CSS、原生 JavaScript | 三页面单页应用、图表、表单、弹窗和对话交互 |
| 后端 | Node.js、Express | 静态页面服务、数据同步、模型调用和业务 API |
| 数据库 | SQLite | 保存活动、导入记录、模型对话和授权连接 |
| 模型接入 | OpenAI、Anthropic、OpenAI-compatible | 支持 OpenAI、Anthropic、DeepSeek、Kimi、千问和自定义模型 |
| 数据文件 | CSV、GPX、TCX | 手动导入跑步活动；单文件最大 10 MB |
| 外部数据 | MCP、OAuth 2.0 | 授权连接运动平台并同步活动数据 |
| AI 能力 | 本地规则、训练 Skill、外部大模型 | 生成本地分析、训练建议和未来训练计划 |
| 测试 | Node.js Test Runner | 覆盖数据解析、指标计算、训练计划和模型提示加载 |

## 后续大功能一：训练计划与执行闭环

这项功能让产品从“分析已经跑过的训练”升级为“陪用户完成接下来几周的训练”。系统需要建立完整的跑者档案，包括目标比赛、目标成绩、个人 PB、每周可训练时间、训练习惯和伤病限制，同时结合近期跑量、心率、睡眠、HRV、恢复状态和主观感受判断当前承受能力。

在此基础上，Agent 可以生成并持续调整多周训练计划，把轻松跑、长距离、节奏跑、间歇跑、力量训练和休息日组织到训练日历中。用户可以看到每天的课程目标，完成训练后进行打卡，记录实际距离、配速、心率、RPE 和身体感受；当恢复状态明显变差或训练负荷增长过快时，系统应主动降低强度或安排恢复，而不是机械执行原计划。计划还应支持用户手动编辑、重新生成、跳过和说明调整原因，形成“状态评估、计划生成、执行反馈、动态调整”的完整闭环。

可以增加的具体功能：

- 跑者档案与目标比赛设置，包括个人 PB、可训练时间、训练偏好和伤病限制。
- 多周训练计划生成，支持基础期、强化期、比赛专项期和减量期。
- 周训练日历和单日课程详情，展示目标距离、配速区间或主观用力程度。
- 训练打卡，记录实际完成情况、RPE、身体感受、疼痛情况和备注。
- 恢复自适应调整，根据睡眠、HRV、静息心率和近期负荷降低强度或跑量。
- 计划编辑、重新生成、跳过、延期和调整原因记录。
- 计划完成率、连续训练周数和执行偏差分析。
- 计划导出，以及经用户确认后同步到受支持的外部运动平台。

## 后续大功能二：训练洞察与长期陪伴

这项功能负责把零散活动转化为长期可理解的训练变化。系统可以分析单次跑步的分圈、后半程掉速、心率漂移、步频、海拔和配速稳定性，也可以聚合周、月、赛季数据，展示跑量、强度分布、恢复趋势、个人纪录和训练连续性。在此基础上，可以生成周报和阶段性训练报告，解释进步来源、疲劳信号和下一阶段的关注点，并结合目标比赛给出成绩预测和配速策略。

长期陪伴还意味着保留用户的目标、偏好和历史决策，让 AI 能理解“这个训练计划为什么这样安排”“上次调整后效果如何”，并在多轮对话中保持连续上下文。报告可以支持图片或 PDF 分享，数据也可以按训练周期归档和对比。两个大功能共享同一套跑者档案、活动数据和训练上下文，最终形成一个既能规划训练，又能解释长期变化、持续陪伴用户的跑步 Agent。

可以增加的具体功能：

- 单次跑步详情，展示分圈、后半程掉速、心率漂移、步频、海拔和配速稳定性。
- 周报、月报和赛季报告，汇总跑量、强度分布、负荷变化和恢复趋势。
- 长期趋势对比，查看训练周期、配速、心率和个人纪录的变化。
- 训练强度分布和负荷分析，识别连续高强度、训练单一或负荷增长过快。
- 目标比赛成绩预测、配速策略和比赛前减量建议。
- 多会话历史，按比赛计划、伤病恢复、日常训练等主题保留上下文。
- AI 对历史建议进行追踪，说明计划调整后的实际效果。
- 报告分享，支持导出图片或 PDF，并按训练周期归档和对比。
