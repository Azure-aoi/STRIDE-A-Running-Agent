# STRIDE OS Agent 审查修复日志（2026-11-03）

## 概要

本轮修复来自 Agent 侧测试与代码审查，覆盖模型计划绕过、会话隔离、心率档案统计、超时、记忆边界和 SSE 续传。

| 项目 | 结果 |
|---|---|
| 自动化测试 | 87 项通过，0 失败 |
| Agent 固定评估 | 30 条通过，得分 100 |
| 数据库结构 | `memory_items` 新增属性 facet 和替代状态字段，自动迁移 |

## 修复内容

### 1. 外部模型不能绕过训练计划工具

问题：

- 外部模型可以返回一段计划文本，不调用 `previewPlanWrite`，仍被标记为完成。
- 固定评估全部使用本地模式，没有覆盖该行为。

修复：

- 检测到计划类问题且运行结果没有计划预览时，运行时自动调用确定性的 `previewPlanWrite`。
- 自动使用服务端跑量、比赛日期、不可训练日和心率建议规则生成计划。
- 最终回答改为以确定性计划结果为准，不再保留模型未经工具校验的替代计划。
- 新增原生模型故意跳过计划工具的回归测试。

### 2. 运行期间禁止切换会话

问题：

- 运行中切换会话时，旧运行的流式回答可能追加到新会话页面。

修复：

- Agent 运行期间禁止切换、新建、删除会话或清空当前对话。
- 提示用户先等待完成或停止运行。
- 运行轨迹记录所属会话，事件继续使用当前运行 ID。

### 3. 心率档案按训练日汇总并按时长加权

问题：

- 同一天的自动分段被当成多次独立跑步。
- 当前数据 30 条心率记录实际只来自 13 个训练日，且多条短于 3 km。

修复：

- 先按中国时区训练日合并记录。
- 同一天的多个分段按跑步时长加权计算平均心率。
- `sampleCount` 表示训练日数量，新增 `activityCount` 表示原始记录数。
- 增加同日分段和时长加权测试。

### 4. 记忆抽取不再影响已完成回答

问题：

- 记忆抽取与用户回答共用 120 秒 Run 超时。
- 回答已经生成后，如果抽取超时，运行可能被标记为取消。

修复：

- 模型回答完成后立即清理 Run 超时并保存完成状态。
- 记忆抽取在用户回答完成之后继续执行。
- 抽取失败只记录审计步骤，不回滚已经完成的回答。

### 5. 计划确认使用服务端冲突结果

问题：

- 前端使用本地训练日历缓存计算冲突。
- 用户未打开日历页时，可能错误显示“0 天已有课程”。

修复：

- 直接使用 `preview.conflicts` 中的服务端结果。
- 仅当服务端没有返回冲突字段时才回退到本地缓存。

### 6. 修正记忆重要性 0

问题：

- `Number(importance) || 0.5` 会把合法值 `0` 转成 `0.5`。

修复：

- 使用显式有限数字判断。
- 保留 `0`，仅缺失或非法值使用默认重要性。
- 增加创建和更新 `importance: 0` 的测试。

### 7. SSE 续传和客户端恢复

问题：

- SSE 没有事件 ID，断线重连会重放完整历史。
- 重复的 `tool.started` 会追加重复轨迹。
- 永久断线时前端可能一直保持“运行中”。

修复：

- 服务端为每条 SSE 事件增加递增 ID。
- 读取 `Last-Event-ID`，只重放缺失事件。
- 前端记录已处理事件 ID，避免重复更新。
- 连接错误后轮询运行详情；运行结束后恢复回答、确认计划并清理轨迹。

### 8. 计划意图和上下文预算

- 扩展非标准计划请求识别，例如“给我编个七天练法”。
- 收紧普通问题识别，避免“最近训练怎么样”被误判为计划请求。
- 系统上下文超过 Token 预算时，依次裁剪低优先级记忆、知识、日历、近期活动和历史周期数据。
- 返回 `budgetSatisfied`，便于判断最终上下文是否仍在预算内。

### 9. Readiness 和记忆边界

- COROS 没有训练负荷时，使用跑量变化和训练频率计算代理负荷。
- readiness 返回 `loadSource`，区分真实训练负荷和历史代理负荷。
- 记忆使用 `scope + attribute` 结构化 facet 判断冲突；同一天的冲刺类型和户外场地偏好可以同时保留。
- 同一天的可用性、同一训练类型或同一场地类型发生变化时，旧记忆才会被替代。
- 手动记忆 API 使用固定类型白名单。
- 只有失败或已取消的 Run 允许重试。
- 全马、半马、10K 和 5K 目标都可以计算目标配速。
- 移除 Run 完成后已经无法送达的 `memory.created` SSE 事件。

### 10. 外部模型评估入口

- 固定评估默认仍使用本地模式。
- 设置 `EVAL_MODEL_API_KEY`、`EVAL_MODEL_PROVIDER`、`EVAL_MODEL_BASE_URL`、`EVAL_MODEL_NAME` 等环境变量后，可以运行真实外部模型评估。

## 行为说明

- 固定评估默认使用本地模式，也可以通过环境变量切换到真实外部模型。
- 训练日历中的旧计划不会自动覆盖，需要重新生成并确认。
- 已替代的长期记忆保留数据库审计字段，但不会进入模型上下文或记忆列表。
