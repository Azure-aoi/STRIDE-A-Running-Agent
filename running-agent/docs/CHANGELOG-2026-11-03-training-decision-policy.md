# STRIDE OS 训练决策策略调整日志（2026-11-03）

## 概要

| 项目 | 内容 |
|---|---|
| 问题 | 高心率会把计划直接压成恢复周，导致长期缺少强度课 |
| 新原则 | 跑量和比赛日期决定计划；心率只形成个人档案和过程建议 |
| 比赛前 30 天以上 | 每周至少两次速度或节奏刺激 |
| 比赛前 30 天以内 | 减少短间歇，增加比赛配速跑和专项长距离 |

| 测试结果 | `npm test` 共 73 项通过，0 失败 |
| Agent 评估 | `npm run evaluate:agent` 共 30 条通过，得分 100 |

## 原决策问题

旧版训练模板同时使用平均心率、跑量涨幅和 readiness 标签：

```js
const avgHr = dashboard.current.avgHeartRate || 0;
if (
  dashboard.readiness?.label === "负荷偏高" ||
  (runs >= 3 && avgHr >= 165) ||
  (dashboard.changes?.distancePct > 35 && weeklyKm >= 30)
) {
  return "recovery";
}
```

这会产生两个问题：

1. 遗传性高心率或炎热天气可能被误判为训练强度过高。
2. 一旦进入恢复模板，整周没有速度或节奏课，训练刺激长期不足。

## 新决策规则

### 计划选择

训练模板只根据以下信息选择：

- 最近 28 天平均周跑量。
- 距离比赛天数。
- 可训练日。
- 伤病限制。
- 用户明确偏好。

心率不参与：

- 模板选择。
- 强度课次数。
- 强度课删除。
- 跑量增减。
- 恢复周判定。

### 周跑量分档

| 最近周跑量 | 模板 |
|---|---|
| 低于 15 km | 基础速度建立周 |
| 15–50 km | 稳态进阶周 |
| 达到 50 km | 比赛专项进阶周 |

基础速度建立周也保留两次低风险速度刺激：

- 轻松跑后短加速。
- 短坡跑或短法特莱克。

稳态和进阶模板均包含两次质量课和一次长距离。

### 比赛日期

距比赛超过 30 天：

- 每周至少两次速度或节奏刺激。
- 质量课之间至少间隔 48 小时。

距比赛 30 天以内：

- 使用 race 专项模板。
- 减少短间歇和阈值堆叠。
- 增加比赛配速跑。
- 增加包含比赛配速段的长距离。
- 比赛前 14 天内进一步缩短比赛配速课和长距离。

比赛配速根据跑者档案中的目标比赛和目标成绩计算。例如珠海马拉松目标 `3:30:00` 对应约 `4:59/km`。

## 个人心率档案

新增 `buildHeartRateProfile(activities)`：

- 默认读取最近 30 次含平均心率的跑步。
- 计算平均值、中位数、个人常见区间和近期偏移。
- 少于 3 次时标记为样本不足。
- 输出固定标记 `usage: "advisory-only"`。

完整档案会进入：

- 训练仪表盘。
- Agent 系统上下文。
- `getTrainingMetrics` 工具结果。
- 本地教练报告。

心率档案的使用边界：

- 可在强度课中建议跑者降组、减速或停止。
- 不因历史心率偏高提前删除整周强度。
- 跑者根据实时主观状态拥有最终决定权。

## 训练计划输出

计划现在新增：

- `daysToRace`
- `decisionBasis`
- `intensitySessions`
- `intensitySessionCount`
- `heartRateGuidance`

输出会明确写出：

- 最近周跑量和距离比赛天数。
- 心率未参与计划难度和强度数量决策。
- 本周两次强度课的具体日期。
- 课中退让条件，而不是提前删除强度。

## 其他修复

长期记忆和跑者档案中的“跑不了”“去不了”“不能跑”“无法跑”等表达现在会被识别为不可训练日。

明确不可训练日会从可用日中移除，避免同一天同时出现在“可用”和“不可用”两个集合中。

## 行为边界

- 现有训练日历中的旧计划不会自动删除或覆盖。
- 新计划需要重新生成并在预览中确认后才会写入日历。
- 心率仍用于信息展示、个人档案和课中建议，不会被完全隐藏。
- 计划仍受伤病、不可训练日和用户手动调整约束。
